# 架构设计

## 分层

| 层 | 内容 | 更新频率 | 是否进入 Git |
|---|---|---:|---|
| 上游引擎 | Squirrel、librime、插件 | 低 | 只记录版本和校验值 |
| 产品配置 | 五笔拼音方案、界面、品牌 | 中 | 是 |
| 基础词库 | 五笔编码与公开词频 | 中 | 是，必须记录许可证 |
| 预测模型 | `predict.db` | 中 | Release 或 Git LFS，不进普通 Git |
| 个人数据 | 用户词频、输入历史、私有语料 | 高 | 否，单独加密备份 |
| 构建产物 | `.app`、`.pkg`、缓存 | 高 | 否 |

## 输入链路

```text
键盘编码
  ├─ 五笔 table_translator（最高优先级）
  ├─ 拼音 script_translator（低优先级补充）
  └─ filters（简体输出、去重、排序）

已上屏文本
  ├─ predict_translator（通用数据库，负责冷启动）
  └─ personal_predict.lua（个人数据库，负责加权和补充）
```

五笔优先是产品的不变量。预测候选只在已经上屏后出现，不能抢占正在输入的五笔候选。

## v0.5 联想合并

1. **通用候选**：`librime-predict` 查询只读 `predict.db`，让新用户安装后立即看到高频联想。
2. **个人候选**：Lua 查询本机 `personal_predict.userdb`，同一搭配出现两次后参与排序。
3. **合并规则**：个人候选使用更高质量值插入同一个联想段，再由 `uniquifier` 去重；通用库没有当前前词时，个人候选仍可独立显示。
4. **编码无关**：查询键只使用已经上屏的汉字，因此前词来自五笔还是拼音不影响联想。

整句语法模型不属于 v0.5 范围。它会介入正在输入时的分词和候选排序，必须在后续版本独立测试，不能破坏五笔优先。

## 隐私边界

稳定版完全离线。个人语料放在 `features/prediction/corpus/private/`，该目录被 Git 忽略。未来即使增加云端模型，也必须做成显式开关，默认关闭并清楚说明上传内容。
