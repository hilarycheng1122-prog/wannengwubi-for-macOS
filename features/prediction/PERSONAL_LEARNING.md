# v0.4.0 个人学习联想

## 产品目标

万能五笔在本机记录用户连续上屏的词语，逐步学习“上一词 → 下一词”的个人搭配。预测完全离线，不依赖云服务和大模型，不改变五笔、拼音的原始候选顺序。

静态 `predict.db` 仅作为可选冷启动兜底；个人联想有数据时始终优先。

## Alpha 1 范围

- 记录连续两次正常中文上屏形成的个人搭配。
- 标点、英文直输、撤销、退格和密码类输入不参与学习。
- 根据使用次数与最近使用时间排序，最多显示 7 个候选。
- 个人数据只保存在 `~/Library/Rime/`，不进入 Git，也不随配置发布。
- 提供暂停学习、暂停联想、清空历史和导出备份能力。
- 当前只联想一轮；整句多级上下文留到后续 Alpha。

## 本地数据

每条记录至少包含：

```text
前词    后词    使用次数    最后使用时间
```

建议使用独立数据库 `personal_predict.userdb`，不修改现有五笔用户词典。数据库损坏或缺失时，正常输入必须继续工作。

个人数据目录、导出文件和测试样本必须被 `.gitignore` 排除。

## 排序规则

Alpha 1 使用可解释的确定性分数：

```text
个人得分 = log(1 + 使用次数) + 最近使用加权
```

候选合并顺序：

1. 个人搭配候选；
2. 可选静态候选；
3. 去重后截取前 7 项。

较久未使用的记录逐步降权，但不在后台自动删除。

## 隐私与安全边界

- 默认只记录通过万能五笔提交的文本，不能读取当前文档全文。
- 切换到 ASCII 模式、密码输入框或关闭学习开关时不记录。
- 所有数据本机保存，不联网，不做遥测。
- 清空操作执行前必须生成可恢复备份。

## 技术路径

1. 先验证鼠须管自带 `librime-lua` 能否可靠监听提交、创建零长度预测候选并持久化数据。
2. 如果 Lua 原型无法稳定处理提交历史和候选段，则基于 `librime-predict` 开发独立 C++ 插件。
3. 插件方案复用 librime 的本地数据库能力，并随定制鼠须管安装包一起签名和发布。

## 验收标准

- 连续输入“万能”“五笔”3次后，再上屏“万能”时，“五笔”进入个人联想候选。
- 更常用、近期使用的个人搭配排在更前。
- 关闭学习后不增加频次，关闭联想后不显示候选。
- 重启鼠须管后学习结果仍然存在。
- 清空或损坏个人数据库不影响五笔、拼音正常输入。
- 单次查询目标耗时低于 10 ms，个人数据库长期使用控制在几十 MB 内。
